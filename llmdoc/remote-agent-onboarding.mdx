# 远程编码代理接入（AGENTS.md 方法论）

让外部编码代理（Codex 等）通过 AgentDock 开发某个项目时，为其编写项目 `AGENTS.md`。
典型方向两种：**Codex 在本机、AgentDock 在远端**（操作远端机器）；**Codex 在远端
Linux、AgentDock 在本机**（远端代理连回来操作本机）。方法论双向通用。
发现机制基础：AgentDock 的 `workspace_context` 会自动发现工作区 AGENTS.md 继承链
（tool-system/context-tools），所以这份文件对任何经 AgentDock 连入的代理都生效。

## 模板与实例

- 模板（含完整骨架）：本机 `dist/AGENTS.remote-project.md`；
- 实例：`dist/AGENTS.san-action.md`（Cocos 项目）、`dist/AGENTS.p2wlan-remote.md`（远端
  Codex 连回本机）。**dist/ 不进 git 且实例含机器名/路径等隐私**——模板内容以本页为准沉淀，
  实例只在本机留档，不复制进仓库或对方仓库的公开文档。

## 必写七要素

1. **方向声明（放最前）**：项目真实位置（谁的磁盘、绝对路径）、代理在哪、本地工作目录
   只是锚点（"没有代码副本，禁止本地找代码/禁止 git init"）。
2. **工具路由表**：逐任务指定 agentdock 工具（read_file/file_edit/exec_command/
   session_observe/session_act/view_image/browser_*），并**显式禁止本地对应工具**——
   模型默认偏内置，不压住就会在本地空转。例外清单：读 AGENTS.md 本身、规划、检索公开资料。
3. **执行语义**（契约见 execution-model 与 tool-runtime）：
   - 路径一律用项目所在机器的绝对路径（相对路径落到 `~/AgentDock` 默认目录）；
   - 命令异步：`exec_command` 长任务返回 running session，`session_observe` 轮询、
     `session_act` 停止；`timeout_ms` 上限 24h；
   - 输出 4MiB 截断：大日志重定向 /tmp 再 read_file 或 grep；
   - **无沙箱红线**：以服务 OS 用户全权限运行——破坏性操作先确认、禁止 `rm -rf` 不确定路径、
     改前 `git status`、每次 `file_edit` 后回读验证；
   - 连接故障不循环重试，提示检查服务与 MCP 定义，禁止把错侧路径拼进参数。
4. **PATH 陷阱（最容易翻车）**：AgentDock 子进程是最小环境白名单（security/env-isolation），
   launchd/服务环境 PATH 极短——`node`/`cargo`/`pyenv shims` 等用户级工具 **不可见**
   （实测：`/usr/local/bin/node`、`/Users/<user>/.cargo/bin/cargo` 都会 command not found）。
   命令必须写绝对路径或前缀 `PATH=...`；在目标机上用最小 PATH 实测后写死。
5. **项目自有约束优先**：项目仓库自带 AGENTS.md/skills/docs 时，规定第一步先 `read_file`
   读它们，且优先级高于本文件；本文件只做传输层与路由。
6. **常用命令落地**：构建/测试/验证命令按实际环境写好（含绝对路径），不让代理猜。
7. **汇报约定**：改动文件（项目机绝对路径）+ 验证输出关键行 + 未完成事项及原因。

## 多实例接入（一个客户端连多个 AgentDock）

Codex 等客户端的 `config.toml` 支持任意多个 `[mcp_servers.<key>]`——每实例一个 key、
各自的 url 和 **各自的 Bearer Token**（不跨实例复用）。适用多机协作（Mac + VPS 各一个
AgentDock，一次会话跨设备调度）。

- **命名即路由**：各实例工具名完全相同（都叫 read_file/exec_command…），客户端按
  服务器 key 区分。AGENTS.md 的工具路由表必须写明「哪类任务用哪个服务器 key 的工具」，
  否则模型选错机器是真实风险。
- **上下文成本**：每实例贡献整套工具 schema（各约 28 个）——只保留需要的实例，
  实例侧关闭不需要的能力（browser/ACP 等 capability-aware 剔除）。
- **同机多实例**：core 不做单实例仲裁，且默认共享 `~/.agentdock` 状态目录——
  同机跑多个 core 必须各自独立 `AGENTDOCK_HOME`（或用 Docker 容器隔离），否则锁与
  状态文件互相踩。
- **分层别混**：这是客户端配置层的事；把一个 AgentDock 当另一个 AgentDock 的动态 MCP
  挂载是错误分层（丢失认证语义与内置工具面）。

## MCP 接入样板（按监听方式）

URL 构成规则：**客户端可达的 origin + `/mcp`**；凭据只放 `Authorization: Bearer` 头，
永不进 URL。端口默认 8765。

| 监听方式 | 客户端位置 | MCP 地址 |
|---|---|---|
| 仅本机（loopback，默认） | 同机 | `http://127.0.0.1:<port>/mcp` |
| 局域网（`AGENTDOCK_HOST=lan`） | 同机 | `http://127.0.0.1:<port>/mcp`（回环始终监听） |
| 局域网 | 同网段其他设备 | `http://<服务机私网 IP>:<port>/mcp`——多网段每个 IP 一个；macOS 主界面连接信息会逐个列出 |
| 临时公网（quick tunnel） | 任意 | `https://<随机子域>.trycloudflare.com/mcp`——tunnel 重启后变化，以主界面当前值为准 |
| 固定域名（named tunnel） | 任意 | `https://<你的域名>/mcp`（= `AGENTDOCK_SERVER_URL` + `/mcp`） |
| stdio | 同机 | 无 URL，客户端直接把 `agentdock --stdio` 当子进程拉起 |
| 经跨网中继接入 | 客户端本机 | `http://127.0.0.1:<本地中继端口>/mcp`（见下方"跨网中继链路"） |

TOML 样板（Codex；JSON 形态同 macOS 主界面「复制 MCP」按钮输出，供通用客户端）：

```toml
# HTTP 监听（loopback / lan / tunnel 通用，只换 url）
[mcp_servers.agentdock]
url = "http://10.10.10.165:8765/mcp"
[mcp_servers.agentdock.http_headers]
Authorization = "Bearer <token>"

# stdio（同机、不经网络）
[mcp_servers.agentdock-stdio]
command = "/path/to/agentdock"
args = ["--stdio"]
```

```json
{
  "mcpServers": {
    "agentdock": {
      "url": "http://10.10.10.165:8765/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

- **认证**：非回环监听必须 token/OAuth（启动校验拒绝无认证暴露，security/authentication）；
  桌面安装总是生成 token。仅本机裸跑（无 token 的 loopback）才允许匿名——样板统一带头不会错。
- **地址会变的项**：LAN IP 跟随 DHCP（换网段需更新 url；服务重启重新枚举地址）；quick
  随机子域每次 tunnel 重启变化；named 域名稳定。
- **stdio 的取舍**：不经网络、无认证门（能启动进程即信任边界），只适合同机；跨机一律走 HTTP 样板。

## 跨网中继链路（实例不可直达时）

客户端与 AgentDock 不在同一可达网络（跨子网路由不通；公网映射如花生壳对海外客户端
不稳定——实测不可用）时，经一台**双方都可达的中转机**串两级转发：

```
客户端 → 本机回环中继 → 中转机隧道端口 → 目标 AgentDock(127.0.0.1:8765)
       (socat/systemd)   (ssh -L/launchd)
```

- **关键约束：客户端侧 URL 必须落在回环**。MCP 端点默认启用 localhost 保护，
  非回环 Host 头 → 403 `invalid Host header`（契约见 tool-system/mcp-surface）。
  所以中继放在**客户端本机**，客户端 URL 用 `http://127.0.0.1:<port>/mcp`；
  不要把"中转机 IP:端口"直接写进客户端 URL。
- **ssh -L 的转发目标**写目标机的 `127.0.0.1:8765`（回环必监听），不依赖目标机的
  局域网绑定地址。
- **常驻方式**：macOS 中转机用 launchd（KeepAlive 包住 `ssh -N -L`；系统 ssh 不支持
  `ExitOnRemoteFailure`，写了就 255 退出）；Linux 客户端机用 systemd
  （`socat TCP-LISTEN:<port>,bind=127.0.0.1,fork,reuseaddr TCP:<中转机>:<port>`）。
  两跳各有守护进程，断线自动恢复、开机自启。
- 排障按跳：客户端本机中继进程 → 中转机隧道（`launchctl list | grep <label>`、
  `systemctl is-active <unit>`）→ 目标机 AgentDock healthz。

## 部署与验证

- **部署位置**：代理侧的工作目录根（Codex 读自己 cwd 的 AGENTS.md）；若项目代码侧也要
  生效（经 workspace_context 发现），同文件放项目根。
- **连通性验证**（部署后必做）：从代理机 `curl http://<agentdock>:<port>/healthz` 通；
  `/mcp` **无 token 401、带 token initialize HTTP 200**（认证门正常且凭据有效）。
  Codex 配置在 `~/.codex/config.toml` 的 `[mcp_servers.agentdock]`（url + http_headers）。
- 客户端内置工具与 MCP 工具的取舍（何时该压内置、Mac 专属任务只有 MCP 可达）见
  tool-system/client-tool-boundary。
